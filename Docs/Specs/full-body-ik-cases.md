# 全身 IK の正解の動き（下書き）

全身 IK の点を動かしたときの「正解の動き」を、単純なリグの型ごとに決める。決めたものは、型ごとのテスト用リグとテストにする。
持ち物と角度・位置の制限は、いったん入れない（11-08 ユーザー指示）。

「正解」の列は、ユーザーが前に決めたこと（日付）か、決まっていないもの（**要決定**。今の案を書いておく）。

## 言葉

| 言葉 | 意味 |
|---|---|
| 重さ 1 の点 | 定義の重さが 1 の点。骨を引く |
| 軽い点 | 定義の重さが 0 で、乗る骨に重さ 1 の点が無い点。つかむと骨を引く（S88） |
| 向けるだけの点 | 定義の重さが 0 で、乗る骨に重さ 1 の点がある点。骨を回して点を目標へ向けるだけ（S28） |
| Free / Pin / Lock | 点の状態。Pin は「その場を維持する。ただし引っ張ることはできる」、Lock は動かない |
| 付け根の点 / 骨の上の点 | 骨の付け根（関節）に乗る点 / 付け根から離れた所に乗る点 |
| 届く | つかんだ点が目標へ行ける（間の骨を伸ばしきった長さの中） |

## リグの型

骨はどれも長さ 0.3m、角度・位置の制限なし。点は特に書かなければ付け根の点で重さ 1。根を留める定義（腰の Pin あり）と、留めない定義（S98）の両方で見る。

| 型 | 形 | 見ること |
|---|---|---|
| R1 | 一本の鎖 `R─A─B─C` | 先・途中・根を引く |
| R2 | 蝶番のある手足 `S─E(蝶番)─W` | 2 本の骨の IK、Pole |
| R3 | 枝分かれ `R─A─{B1─C1─D1, B2─C2─D2}`（枝の付け根 B1・B2 は骨 A に付く。人型の胸と両腕の形） | 片方の枝を引いたときのもう片方 |
| R4 | 骨の上の点 `A─B` の B の中ほどに点 P | 付け根でない点を引く・留める |
| R5 | 同じ骨に 2 点 `A─B`、B に付け根の点と骨の上の点 Q | 同じ骨の点どうし |
| R6 | 軽い点の鎖 `S─E─W`、S・E は重さ 0、W だけ重さ 1 | 軽い点を引く |
| R7 | 向けるだけの点 `R─A─B`、A に重さ 1 の付け根の点と重さ 0 の点 D | 向けるだけの点を引く |
| R8 | 軸まわりにしか回らない骨 `R─P─K(軸)─A─B`（K は角度制限で 2 軸を回さない骨。親 P は根でない骨） | 軸の骨をはさむ鎖 |
| R9 | 輪 `R─A─{B1─C1─D1, B2─C2─D2}`（R3 の両方の枝を骨 3 本にし、D2 の付け根を D1 にも輪の関節でつなぐ。S105。D1 は D1─D2 の棒のように動く。持ち物は使わない） | 輪の中の点を引く・留める |
| R10 | 両脚 `R─{B1─C1─D1─T1, B2─C2─D2─T2}`（股 B を根 R の左右に出し、膝 C は蝶番で 90° 曲げる。D は足首、T は爪先。しゃがんだ人型の脚の形） | 脚が伸びきる所の先へ根を持ち上げる |

## 決めたこと（11-08）

1. **離れの変わらない 2 点（1-4・1-6・2-3・4-1・5-1）**: つかんだ点を届かせ、Pin の点は必要な分だけ引く。Pin の「その場を維持する。ただし引っ張ることはできる」をそのまま当てはめる
2. **Free の子の骨の向き（1-7・3-3）**: 親に対する向きのまま（FK）
3. **骨の上の点（4-1）**: 骨が回るだけで届かない分は、付け根の Pin も引かれる
4. **角度制限で届かないとき（2-1・6-2。11-09）**: 重い点をつかんでいれば、Pin の点は届かない分だけ引かれる（2-1。間の関節を曲げきれず縮められないときは、
   Pin の点が目標から離れる向きへ、今の開きの距離になる所まで動く）。軽い点をつかんでいれば重い点は動かさず、つかんだ点は届く所で止まる（6-2）

ほかに足したい型・場合があれば足す。

## 今の結果（11-08）

テストは `Tests/Editor/FullBodyCaseTests.cs`（56 件。根を留める定義・留めない定義の両方）。マウスを 20 回に分けて動かし、毎回キーの姿勢から解き直す（窓と同じ）。
「跳ばない」（I2）は、どの骨も 1 回でマウスの動きの 4 倍 + 5mm より大きく動かないこと。Pin が「留まる」は 5mm 以内。
I1 は全部の場合で、最後に窓で離したときと同じ手順（引かれた Pin・Lock の点を骨の今の場所へ付け直し、つかむのをやめ、今の姿勢をキーにする）で解き直し、骨が 1mm・0.5° より変わらないこと。
I3 は伸びきる場合（1-3・1-8・3-2）で、伸びきった後にさらに引いても伸びきったまま（5mm より縮まない。キーの曲がりへ戻らない）こと。I4〜I6 は場合ごとの正解の中で見ている。

全部通る（初めは 1-3・1-4・1-5・2-2・2-3・3-2・8-1 が通らなかった。11-08 に直した。下の表）。

### 直したこと（11-08）

| | 原因 | 直し方 |
|---|---|---|
| 1-4・2-3 | 離れの変わらない 2 点を、「つかんだ点の骨の上の点」と「つかんだ骨にぶら下がる骨の付け根の点」だけで見分けていた（逆向きの、つかんだ点が付け根の点で Pin の点が親の骨にある場合を数えず、根を留めない定義では数えなかった）。Pin の点は伸びきったときだけ引き、近すぎるときはソルバー任せで、Pin の点が最小の所から 7cm ずれて押され、最後に別の答えへ跳んだ | 「同じ骨の上」か「付け根の点は親の骨に付く」で見分け（RigidPair）、どちら向きでも、どちらの定義でも、Pin の点をつかんだ点から決まった離れの所へ最小だけ運ぶ（遠すぎても近すぎても） |
| 1-5 | Lock の点と離れの変わらない点を引くと、ソルバーが Lock の点と取り合って骨を回しきれず、つかんだ点が元の場所に残った | つかんだ点の目標を、Lock の点から決まった離れの球の上で一番近い所にして解く（ClampToLock） |
| 1-3 | 伸ばした姿勢から解き始める処理（StraightenPath）が、道の上の Pin の点の骨を根（腰）とみなし、その骨だけを運んで、親（根）を元の場所に残した。ソルバーは解き始めの姿勢で骨の長さを測るので、伸びた骨のまま解き、Pin の点が動かなかった | Pin の点の骨の根の方の骨も、一緒に運ぶ |
| 3-2 | 枝が骨 1 本で、最初から伸びきっていた（テストの置き方の誤り。B2 は骨 A に付くので、B2─C2 の離れは変わらない） | 枝を骨 2 本にした（3-2）。骨 1 本の形は 3-4 に分けた |
| 3-4（留める） | 道の外の Pin の点を運ぶ量（BranchShifts）を、Pin の点を外して解いた姿勢で測っていた。その姿勢では体がキーの形へ戻って起き上がるので、運ぶ量が多すぎ（マウス 4cm に 15cm）、引かれ始めの 1 回で跳んだ | その量の何割で届くかを探し、届く一番小さい割合だけ運ぶ（LeastBranchScale）。離れの変わらない Pin の点の運ぶ量は絞らない |
| 3-4（留めない） | 点の間の道の外にぶら下がる根の側の骨（R）の向きを決める決まりが無く、反復の途中の形で残った。届かなくなったところで 1 回 45° 回った | 根を留めない定義で、点の掛かった骨が 2 本以上なら、それらをつなぐ木の一番上の骨より根の側の骨を、一番上の骨に付けて元の向きのまま動かす（CarryRootSide。11-08 ユーザー決定「A に付いて回る」）。点が 1 つだけなら今までどおり（1-8） |
| 2-2 | Pole（手足の付け根と先を結ぶ軸まわりに回す。SnapPole）は、Pole の骨にほかの点があると Pole にしなかった（膝の点のように関節の場所を決める点を除くため）。付け根の S の点も除かれ、Pole がふつうに骨 S を向けて Pin の W を引いた | 除くのは、蝶番の骨の点と、Pole の骨の付け根から離れた点だけにする（付け根の点は軸の端にあり、関節の場所を決めない） |
| 8-1 | 向けきれない分を親が回して向ける処理（AimWithParent）は、動かせない点で決まる軸の骨（axisLock。鎖骨・持ち物の握り）だけに効き、角度制限で 2 軸を回さないにした骨は別の扱いだった（向けたあと仕上げで制限に戻され、36° 残った）。テストのリグは K の親が根の骨で、根は回さない決まりにも当たっていた | 2 軸を回さない骨も、残りの 1 軸まわりにだけ回る骨（axisLock）にする。リグは K の親を根でない骨にした |

### コードの置き場（11-08 整理）

重い点をつかんだときの解き直しは 3 つのファイルに分けた（挙動は変えていない。整理の前後で、テストで重い点をつかんで解いた 2440 回の姿勢が 1e-5 まで一致）。

- `FullBodyRig.HeavyGrab.cs`: 解き直しの流れ（保持解き → 道の上の Pin の点を運ぶ → 道の外の Pin の点を運ぶ → Lock の点が動けば絞る → 運び足し）と、目標の作り方（`HeavyEffectors`）
- `FullBodyRig.Path.cs`: つかんだ点から根への道の上の骨の扱い（`PathStretch`・`StraightenPath`・`LockLimit`・`LimbRoot`）
- `FullBodyRig.Rigid.cs`: つかんだ点と離れの変わらない点の扱い（`RigidPair`・`RigidShift`・`ClampToLock`）

`HeavyEffectors` の運ぶ割合は 1 つ（`fraction`）にまとめた。道の外の Pin の点だけを別に絞るとき（`LeastBranchScale`）は `branchScale` を渡す。

## 角度制限を入れた場合（11-08）

11-08 ユーザー指示「姿勢制御のテストに角度制限を加えたバージョンを追加してテスト」。どの場合も、角度制限なし・広い制限・狭い制限の 3 通りで流す（`FullBodyCaseTests.Limits`）。
制限は根でない骨のどの軸にも同じ範囲（決めてある軸はそのまま）で、基準姿勢（テストのキーの姿勢）からの回り。遊びは 15°。

- 広い（Wide）: ±90°。どの場合もほとんど当たらない。制限の仕組みが、当たらない間は答えを変えないかを見る
- 狭い（Tight）: ±30°（遊びを入れて ±45°）。鎖の 50° の曲がりを伸ばしきる・大きく曲げる場合に当たる

どの場合も I7 を、引く回ごとと離した後に見る（`MeasureLimits`）。場合ごとの正解は、制限なしのときの値のまま見ている。

今の結果（11-11）: 210 件（R10 の 6 件を含む）がすべて通る。11-10 は 10-1 の狭い制限の 2 件が外れていた（下の「両脚の結果」。11-11 に直した）。
11-09 までは、狭い制限の 5-1 の 2 件（Pin の点が留まる・引かれる、根を留める）が I2 で外れていた（A が最後の回に 31mm・83mm 跳ぶ）。11-10 に直した（下の「跳ぶ不具合の直し」）。
2-1・6-2 は、正解を決めて（決めたこと 4）テストを合わせた。2-1 はそのままでは S が最小（49mm）の所から 73mm 横にずれて引かれたので直した（下）。

3-4（留める）は通るが、最後の 3 回で枝の付け根が平面の外へ ±30° 前後振れる（向きも入れ替わる）。I2 の基準（1 回にマウスの動きの 4 倍 + 5mm）には収まる。

### 制限を越える・届かない不具合の直し（11-08）

- 1-3（留める）: 重い点を引いて解き直すときは、道を伸ばした姿勢から解き始める（`StraightenPath`。引いた骨は向きを変えない）。
  点で向きの決まらない先の骨（解かない骨）は、解き始めの姿勢で親から見た向き（`restRelative`）のまま親に付いて動くので、親だけが回った分、制限を越えたまま残った（71°。制限は 45°）。
  仕上げの `ClampLimits` は解かない骨を回さない。**解き始めの姿勢で親から見た向きを、範囲 + 遊びに収めてから使う**（`PrepareLimit`）。解き始めが元の姿勢なら何も変わらない
- 3-4（留める）: 道の外の Pin の点（手足の先）を運ぶ量は、手足の付け根から目標までの長さで決める（`BranchShifts`）ので、制限で手足を目標へ向けきれないと足りず、
  体ごと運べずに 26mm 届かなかった。**届かなかった分を道の上の Pin の点へ運び足すとき（kCarryRefines）、引かれている手足の先の Pin の点にも同じだけ運び足す**
- 2-1（11-09）: 目標が近すぎて、間の関節を角度制限で曲げきれないとき、届かなかった分（つかんだ点から目標への向き）をそのまま Pin の点へ運び足していたので、
  S が横へ動いた。**つかんだ点の目標が、Pin の点から今の開きより近ければ、Pin の点を目標から離れる向きへ、離れがその開きになる所まで運ぶ**（`SpanShift`。
  根を留める定義の運び足し `PathRefine` と、根を留めない定義の `ResolveUnpinnedHeavyGrab` で使う）。遠すぎるときは今までどおり

### 跳ぶ不具合の直し（11-08。Fable の見立て）

- 3-4: 軸ごとの制限では、止めに当たった軸のほかの軸は範囲の中なら逆らわない。止めに当たった関節が丸めの誤差で平面の外へ少し傾くと、
  反復のたびに傾きが育ち、回ごとに手前・奥・平面のどれかの答えへ跳んだ。**止めに当たっている関節では、元の姿勢（キー）から動いていない軸（1e-3 rad 以内）をキーの値に留める**（`SolveLimit`・`limitKey`）。
  当たっていない関節には何もしない（制限の無いときと同じ答えのまま）。
  根を留めない定義では、届かないときに一直線に並べる処理（`StraightenToward`）が最初の骨を目標へ向けてから後ろを制限で切るので、制限で曲がった鎖が 34° 回った形へ跳んだ。
  **制限で切った鎖を、留めた点のまわりに丸ごと回して先を目標へ向ける**（制限に当たらなければ回す量は 0）。どちらも入れて、3-4 の跳びは両方消えた。
- 5-1: 骨 B は点 2 つで向きが決まるので、遊びのばねは全部親（根）の A に掛かる。A を B の軸まわりに転がすと、B の振りがひねり（範囲の中なら逆らわない）へ移るので、
  ばねが硬くなるにつれてその答えが有利になり、20 回目に切り替わった。Fable の案「遊びのばねは子だけ回す」では 5-1 が通るが、
  骨ごとに重さを自分の分だけにした鎖（S96）で、曲がりを根元へ配るのが弱まり、先端が 4.6cm 届かなくなる（`Solver_OwnWeight_SpreadsTheBendAlongAChain`。3cm 以内のはず）。
  「子が回せない骨にはばねを掛けない」でも同じに外れる。まだ入れていない
- 5-1（11-10 に直した。Fable の見立て）: 跳びは幾何でなく反復の産物だった。遊びのばねの硬さは今の角度で決まる（越えた量 / 遊び）のに、XPBD の λ を反復をまたいで持ち越していたので、
  柔らかくなった回に前の回までにためた λ を一度に逆向きに吐き出し、骨を遊びの外へ弾き返した。根の位置のばねとの間で行き来し、反復の回数で答えが変わった
  （1 つ目の場合は、遊びの中 35.7° → 止めの 45° → 31° と跳んだ）。**持ち越すのを λ でなく伸び（λ × 柔らかさ）にした**（`SolveLimit`・`limitLambda`）。
  伸びは硬さが変わっても今の角度との間で動くので、逆向きに吐き出さない。遊びの意味（越えるほど硬い）はそのまま（1 つ目の場合は 38° まで少しずつ曲がる）。
  2 つ目の場合（A が自分の軸まわりに転がり、ひねりが 4° から 22° へ跳ぶ）も、これで消えた。λ を持ち越さない形（実験）でも跳びは消えたが、遊びが範囲の端（31°）の硬い壁に潰れたので取らなかった

## 両脚の結果（11-10）

10-1 の 6 件（根を留める・留めない定義 × 角度制限なし・広い・狭い）は、どれも I2 で外れる。ほかの見ること（伸びきるまで留まる・I3・足の向き・I1）は通る。
脚が伸びきる 1 回（腰を 2mm 上げる）で、膝 C1 と爪先 T1 が 23mm 動く（許すのは 13mm）。狭い制限では膝が伸びきる前に制限に当たり、その 1 回で爪先 T2 が 20mm 動く。
全体は 210 件のうち 202 件が通る（外れるのは 10-1 の 6 件と、前からの 5-1 の狭い制限の 2 件）。デモのキャラでも、腰を 10mm 上げる 1 回で膝が 56mm、足が 7° 動いた。

原因は、脚を伸ばしきる所の形そのもの。足首を留めたまま腰が目標へ行くと、伸びきるまでの残りが δ のとき、膝は股と足首を結ぶ線から √(2δ × 骨の長さ / 2) くらい離れている
（残り 2mm で 24mm）。最後の数 mm で膝がその分を一気に詰めるので、「伸びきるまで動かない」（1-3）と「つかんだ点は目標へ行く」（I6）をどちらも守ると、I2 は守れない。
9-5・1-3 も同じ形だが、マウスを 20 回に分けて動かすので、1 回が大きく、許す量に収まっていた。

決めたこと（11-10 ユーザー決定「伸びきる手前から付いてくる」）: 1-3 を緩める。Pin の点は、伸びきる少し手前から少しずつ付いてくる（soft IK）。1-3・3-2・9-5・10-1 も同じ決まり。

### 直したこと（11-10）

- 重い点をつかんで解いた後に、伸ばしきる手前の鎖の Pin の点へ運び足す仕上げを足した（`FullBodyRig.SoftenStretch`）。鎖が伸びる長さを `SoftReach` にして、
  両端の離れとの差を Pin の点の目標へ足し、前の答えから解き直す（今までの運ぶ量で足りていれば何もしない）。道の外の Pin の点は手足の付け根から目標まで（`BranchShifts` と同じ数え方）、
  道の上の Pin の点はつかんだ点の目標まで（`PathStretch` と同じ数え方。道の上の Pin の点全部に同じだけ）で測る。輪でつながった Pin の点どうしはそろえる
- `SoftReach`: 付いてき始める所は、伸ばしきった長さの 3%（`kSoftStretch`）手前と、元の姿勢（キー）での離れの遠い方。そこから幅の 2 倍先でちょうど伸びきる 2 次の曲線
  （残りが (1 − x)² で減り、膝の一直線からのずれが一定の速さで詰まる）。膝の動きは、付いてき始める所でマウスの約 2.9 倍で、伸びきる所へ向けて遅くなる。
  初めは指数で近づけたが、Fable のレビューで「いつまでも伸びきらず、脚が曲がったまま付いてくる」と指摘され換えた。
  元の姿勢から数えるのは、キーですでに伸びきりに近い手足（T ポーズの脚）で、何も引いていないのに Pin の点が付いてこないため（全部の点を回すテストで、腰が 4.8mm ずれた）。
  そのため、ほぼ伸びきったキーでは付いてくる幅が狭く、膝が速めに伸びる（膝のずれ自体が小さいので跳びは小さい）
- 運び足して解くとつかんだ点が届かなくなる（背骨のように骨の多い道を縮めるのは、反復で解くソルバーが苦手）ときは、届く一番多い割合まで絞る。全部か 0 かで切り替えると境目で跳ぶ（Fable のレビュー）
- Lock の点があるときは何もしない（Lock の点を守る絞り込みの答えを崩さない）。片足 Lock・片足 Pin で腰を上げると、Pin の側の膝は今までどおり伸びきる所で速く伸びる
- 手足の長さ（`LimbRoot`）を、解き始めの姿勢でなく元の姿勢で測る（骨の長さは同じ。解き直しを通らないときは解き始めの姿勢が入っておらず、長さ 0 になった）

10-1 は、角度制限なし・広い制限の 4 件が通る。狭い制限の 2 件は I2 で外れる（下の 5-1 の直しの後。前は境目すれすれで通っていた）:
膝は伸びきる前に止め（45°）に当たり（脚は 554mm まで）、ソフト化は効かない（付いてき始める 582mm に届かない）。その後、腰を 2mm 上げるごとに足首が 8〜9mm 後ろへ滑り
（股の遊びのばねの中で脚が回る）、股の角度が落ち着く 1 回で 13.3mm 動く（許すのは 13.0mm）。後ろへ滑ること自体が、「Pin の点は必要な分だけ引かれる」（決めたこと 4）より多く動いている。
決めたこと（11-10 ユーザー決定）: 狭い制限で膝が止めに当たった後も、足首は必要な分だけ付いてくる（届く所のうち元の足首に一番近い所。股と元の足首を結ぶ線の上で、ほぼ真上に股の方へ少し寄る。
股の真下より後ろへは行かない）。決めたこと 4 と同じ。11-11 に直した（下の「直したこと（11-11）」）。それまでに試して外した案:

- 仕上げ（`SoftenStretch`）で、目標から 1mm より外れた Pin の点の目標を、付け根と元の目標を結ぶ線の上の今の手足の長さの所へ置き直す: 足首はほぼ真上へ上がった（z 0.11 → 0.08）が、
  81 回目から腰が横・前へ転がり（最後は 11°）、左右の足首の高さが 43mm ずれ、股が 1 回 18.7mm 跳んだ。3-4 の狭い制限も 1 件外れた（C1 が 7mm 届かない）。
  Fable の見立て: Pin の点をちょうど届く所へ置くと、Pin の点が腰に逆らう力を失い、腰の向きはテストのリグでは硬さ 0.2（さらに `ResolveHeavyGrab` が緩める）でほぼ自由なので、
  股の遊びのばねが抜ける向きへ腰が転がる。付け根を測り直すたびに目標が付いていくので、転がりが育つ
- 運び足しの輪（`CarryPinsToGrabbed` の kCarryRefines）で、取り合いで目標から外れた手足の先の Pin の点を、解いた答えの今の開きを手足の長さにして運ぶ（Fable の案）: 効かなかった。
  この場合は腰（つかんだ点）が届くので `Solved` が解けたとみなし、解き直しに入らない（足首の Pin の点は、つかんだ点と離れの変わる点なので `Solved` が見ない）

- 上の案に、道の外の Pin の点が取り合いで目標から 1mm より外れたら解き直しに入る（`Solved`）・運び足しの輪もそれまで抜けない・根をつかんでいるときは根の向きの硬さを緩めない、を足す:
  根を留める定義では、88 回目までは足首がほぼ真上へ上がった（z 0.11 → 0.10）が、91 回目に後ろへ滑った答えへ戻り、爪先が 169mm 跳んだ（運び足しの輪の 4 回で詰めきれない）。
  根を留めない定義（`ResolveUnpinnedHeavyGrab`）は解き方が別なので変わらなかった。解き直しに入る場合が増え、3-4 の広い制限も外れた（股が 1 回 277mm）。外した

足首の Pin の点は、取り合いで目標から最大 24cm 外れている（腰は届く）。強さ 1 どうしの取り合いの妥協を、股の遊びのばねが決めている。直すには、
運ぶ量を決める所（`BranchShifts`）が角度制限で止まった手足の長さを知る必要があり、根を留めない定義の解き直しにも同じ決まりが要る。大きめの作り直しになるので、いったん止めた（11-10）

### 直したこと（11-11）

- 手足の長さ（`LimbRoot`）を、骨の長さの和でなく、角度制限の中で一番伸ばした長さにした（`LimitedReach`）。関節ごとに、元の姿勢（キー）で親から見た向きから、
  子の骨を親の骨の向きへそろえる向きへ、必ず守る範囲（範囲 + 遊びと元の姿勢の値の広い方。ソルバーの `ClampHard` と同じ）の中で回せる所まで回して測る（曲がる面はキーのまま）。
  制限の無い関節は伸ばしきるので、制限が無ければ今までと同じ長さ
- この長さは、道の外の Pin の点を運ぶ量（`BranchShifts`。根を留めない定義の輪の `CarryLoopPins` も）・伸びきる手前から付いてこさせる仕上げ（`SoftenStretch`。根を留める・留めない定義のどちらの後にも掛かる）・
  Lock の点を守る割合（`LockLimit`）の全部で使う。継ぎ足しの処理は足していない
- 10-1 の狭い制限では、脚は 554mm（膝が止めの 45°）を伸びきった長さとして、その 3% 手前から足首が付いてくる。足首は股と元の足首を結ぶ線の上を動き（最後は z 0.11 → 0.086）、
  目標は届く所にあるので、つかんだ腰と取り合わない。テストに、引ききった後の D1・D2 が最小だけ引かれた所にあるかを足した（`PulledLeast`。6 件とも通る）
- 腰は引ききった所で前へ 7.6° 傾く（前は 13°）。股の遊びのばねと腰の向きの硬さ（0.2）の釣り合いで、股は腰の左右の軸の上にあるので、足首の場所は変わらない
- 試して外した案 (a)（今の手足の長さで置き直す）との違い: 長さを解いた答えから測らず、骨と制限から決まった値にしたので、測り直すたびに目標が付いていく転がりが起きない
